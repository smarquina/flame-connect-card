# Flame Connect Card 0.5.0

## card-mod configuration

Flame Connect Card now preserves the optional `card_mod` configuration when loading the card and when saving changes in the visual editor. CSS strings, nested selector maps, classes, debugging options and Home Assistant templates are passed through to card-mod unchanged.

Install [card-mod](https://github.com/thomasloven/lovelace-card-mod) separately to apply custom styles. For example:

```yaml
type: custom:flame-connect-card
entities:
  flame: light.living_room_flame
  climate: climate.living_room_heating
initial_view: compact
compact_style: chip
card_mod:
  style: |
    ha-card {
      --ha-card-background: "#202a28";
      border-radius: 16px;
    }
```

With card-mod 4, `ha-card` targets both the summary and expanded dialog. Use `ha-card[data-view="chip"]` for the summary or `dialog ha-card` for the dialog only. See the [configuration guide](https://github.com/smarquina/flame-connect-card/blob/main/docs/configuration.md#styling-with-card-mod) and the card-mod documentation for selectors and shadow-root navigation.

## Upgrade

Update through HACS and reload the Home Assistant frontend. Manual installations should replace the attached `flame-connect-card.js` and reload the frontend. Minimum supported Home Assistant version remains **2026.10.4**.

This is an unofficial card designed for the [Flame Connect HA integration](https://github.com/smarquina/Flame-Connect-HA).

## Validation

241 unit/component/contract tests passed with 100% line, branch, statement and function coverage. The browser suite covers 100 cases across Chromium, mobile Chromium, Firefox and WebKit. An isolated Chromium test also loaded the official card-mod 4.2.1 module with a simulated Home Assistant context and verified CSS application to the chip and dialog. Physical theme matching remains subject to user verification.
